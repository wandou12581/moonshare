# 安全模型与限制

## 声明

！！本项目主要由Ai编写代码，不要用在任何严肃场合！！
MoonShare v1 是一个**可信局域网内的只读投屏工具**。它用配对码阻止误连，用会话
token 绑定 UDP 端点，但**视频和控制流量没有加密**。不要把它直接暴露到公网。

## 威胁模型

### 防护目标

1. 同一局域网里的普通用户不能在没有配对码的情况下看到画面。
2. 观看端不能通过协议获得任何输入能力。
3. 未授权的 UDP 数据包不能注入到解码器。
4. 错误配对尝试不能无限暴力枚举。

### 明确不防

1. **同网段抓包**：TCP/UDP 均为明文，攻击者能看到配对码、token 和 H.264 画面。
2. **主动中间人**：没有证书/密钥交换，攻击者可篡改 TCP 和视频。
3. **恶意分享者**：观看端信任手机发来的 SPS/码流；恶意码流可能触发解码器漏洞。
4. **拒绝服务**：大量 TCP 连接/广播可以消耗手机资源；只做了基础限速和 15 秒空闲超时。
5. **公网暴露**：端口映射到公网等于把屏幕交给互联网。

## 配对与 token

- 每次开始共享生成 6 位十进制码（`SecureRandom`，100000–999999）。
- 每个观看者会话生成：
  - 63 位随机 `session id`（16 hex）；
  - 128 位随机 `token`（32 hex）。
- TCP `welcome` 明文返回 session/token；UDP HELLO 必须携带完全一致的 session + token，
  手机才记录观看者端点并开始发送。
- 同一个 IP 一分钟内失败 5 次后拒绝（`rate_limited`）。
- 单观看者：已有会话时直接返回 `busy`，不消耗配对码尝试次数。
- 6 位码空间只有 90 万；限速下仍不抗长时间分布式暴力枚举。**不要把端口暴露到公网。**

## 只读保证

协议中不存在以下消息：

- 鼠标/键盘/触控事件；
- 剪贴板、文件、麦克风、摄像头读取；
- 应用启动、Shell 命令、无障碍操作；
- 任何让手机执行动作的 RPC。

Android 端只创建 `VirtualDisplay` 的输出 Surface，不申请输入注入权限，也不启用
AccessibilityService。PC 端没有发送输入的代码路径。即使观看端被篡改，它也只能
发送未知 JSON 字段，手机会忽略。

## 网络面

| 端口 | 协议 | 暴露内容 | 认证 |
|---|---|---|---|
| 47800 | TCP | 配对、心跳、关键帧请求 | 6 位码 |
| 47801 | UDP | 视频分片 | session + token |
| 47802 | UDP | 发现响应（设备名、端口） | 无 |

发现响应只包含设备型号、端口和 IP，不包含配对码或画面。发现本身可被伪造；
PC 端应让用户确认设备名/地址。

## 建议部署

- 只在家庭/办公室的**专用 VLAN 或可信 Wi-Fi** 使用。
- 关闭路由器上的 UPnP/端口映射，不要把 47800–47802 暴露到公网。
- 跨地点使用 WireGuard、Tailscale、ZeroTier 等 VPN，而不是端口转发。
- 共享结束后点「停止共享」；Android 通知栏也会显示正在录屏。
- 在 Android 系统设置中检查哪些应用有屏幕录制/无障碍权限。

## 如果要做安全加固

优先级从高到低：

1. TCP 使用 TLS（自签证书 + 配对码指纹确认），UDP 使用 DTLS-SRTP 或应用层 AES-GCM。
2. PAKE（SPAKE2/OPAQUE）替代明文 6 位码，避免离线暴力。
3. 对 SPS/PPS/码流做长度和语法校验，限制解码器资源。
4. 发现响应签名，防止伪造设备。
5. 观看端证书固定/二维码带指纹，替代手输 6 位码。

这些不在 v1 范围内，避免给用户“已经端到端加密”的错误印象。
